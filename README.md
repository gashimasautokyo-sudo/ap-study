# 応用情報 過去問アプリ（オフラインPWA）

応用情報技術者試験・午前問題（四肢択一）を、**通信を一切使わずに**スマホで解くための個人用アプリ。

- 試験回を指定して出題／分野を指定して出題
- 間違えた問題は自動で蓄積され、あとから絞って復習できる
- 分野別の正答率グラフ、模試モード（80問・150分）、問題ごとの自分用メモ
- 学習履歴は端末内（IndexedDB）にのみ保存。書き出し／読み込みでバックアップ可

---

## 1. 動かす

### PC で確認する

```bash
py -3.12 -m http.server 8765 --directory app
```

`http://localhost:8765` を開く。localhost は安全なオリジンとして扱われるので Service Worker も動く。

### スマホに入れる（GitHub Pages）

Service Worker は `https` か `localhost` でしか動かないため、**一度だけ** 静的ホスティングに置く必要がある。
`app/` だけを `gh-pages` ブランチに送れば、リポジトリ本体を作り直さずに済む。

```bash
git init
git add .
git commit -m "応用情報 過去問アプリ"
git branch -M main
git remote add origin https://github.com/<ユーザ名>/<リポジトリ名>.git
git push -u origin main
git subtree push --prefix app origin gh-pages
```

その後 GitHub のリポジトリ設定で **Settings → Pages → Source: Deploy from a branch → `gh-pages` / `(root)`** を選ぶ。
数分で `https://<ユーザ名>.github.io/<リポジトリ名>/` が開く。

1. スマホのブラウザでその URL を開く（初回だけ約10MBの問題データを取得する）
2. iPhone は Safari の共有 →「ホーム画面に追加」／Android は Chrome のメニュー →「アプリをインストール」
3. 以降は**機内モードでも起動する**。問題データも学習履歴も端末内で完結する

問題データを作り直したら、`app/` を commit してから次で更新する。

```bash
git subtree push --prefix app origin gh-pages
```

`work/` は `.gitignore` で除外してある（130MB以上あり、元PDFから再生成できるため）。

> **公開範囲について**: GitHub Pages は無料プランではリポジトリを private にしても **URL は誰でも開ける**。
> 収録しているのは IPA の試験問題なので、URL を他人に共有しない前提で使うこと。
> 非公開にしたい場合は Cloudflare Pages ＋ Cloudflare Access（自分のメールアドレスだけ許可）が使える。

### 問題データの読み込み方式

33回分だと `questions.json` が 10MB を超えるので、起動ごとに読み込まないようにしている。

1. 起動時に **`data/version.json`（約90バイト）だけ** を取りに行く
2. `stamp` が端末に記録済みのものと同じなら、本体は取りに行かない（実測 20ms 程度）
3. 変わっていたときだけ `data/questions.json` を取得して IndexedDB に取り込む
4. 取り込みが済んだら `questions.json` を Service Worker のキャッシュから削除する（容量を返す）

そのためオフラインで動くのに必要なのはアプリ本体（13ファイル・約80KB）だけで、
問題データは IndexedDB 側にある。`version.json` だけはネットワーク優先で見るので、
データを差し替えたときに更新を見落とさない。

ホスティングを使わず `app/index.html` を直接開く場合は `fetch` が使えないため、
設定画面から `questions.json` を手で読み込む（オフライン起動も保証されない）。

## 2. 問題データの作り方

IPA が公開している午前問題 PDF から作る。**問題 PDF はスキャン画像でテキスト層がない**ため、
4 段階のパイプラインになっている。

```
① 解答PDF ──機械抽出──▶ work/answers/<回>.json      正解80問 + 大分野(T/M/S)
② 問題PDF ──画像化────▶ work/pages/<回>/pNNN.png    1ページ1枚
③ ページ画像 ─読み取り─▶ work/extracted/<回>_*.json  問題文・選択肢・中分野・解説・図の位置
④ ①③を突き合わせ ────▶ app/data/questions.js       整合検査してバンク生成
```

### ① 正解と大分野を取り出す

```bash
py -3.12 tools/extract_answers.py --pdf-dir "C:\Users\gashi\Desktop\応用情報技術者試験問題、回答"
```

解答 PDF はテキストが入っているので確実。平成28年度以降は大分野（T/M/S）も取れる。
**令和4年度 春期だけは解答 PDF もスキャン画像**だったので、解答表の画像を4列に分けて
拡大転記し `work/answers/r04h.manual.txt` に置いた（すでに反映済み。33回すべて解答確定）。

手入力ファイルは次のどの書き方でもよい。

```
エウイアウ…            ← 80文字並べるだけ
1 エ                    ← "問番号 解答"
1 エ T                  ← "問番号 解答 大分野"（大分野も④の照合に使われる）
```

### ② ページを画像にする

```bash
py -3.12 tools/render_pages.py --pdf-dir "C:\...\応用情報技術者試験問題、回答" --only r07a r07h
```

`--only` を省略すると全 33 回。1 回あたり約 40 ページ / 4.5MB。

### ③ ページ画像を読んで構造化する

ここは Claude Code の**サブエージェントに分担させる工程**。1 回分を前半・後半に分けて 2 エージェントに割り当て、
それぞれが担当ページの画像を読んで `work/extracted/<回>_a.json` / `_b.json` を書く。
エージェント定義は `.claude/agents/ap-question-extractor.md`（Claude Code のプロジェクト設定側）にある。

割り当てるページ範囲は次で出す（実在ページの中央で割る）。

```bash
py -3.12 tools/page_split.py r07a r07h
```

出た範囲を `ap-question-extractor` に渡す。前半は「p000〜pNNN」、後半は「pNNN+1〜最終ページ」で、
境界の1ページは文脈確認用に読んでよいが**「問N」の見出しが担当範囲外にある問題は出力しない**と伝える。
これで前半・後半の問番号が重複せず、合計 80 問になる。5 回分（10 エージェント）ずつ流すのが扱いやすい。

平成27年度以前は解答 PDF に大分野欄がないため、その旨をエージェントに伝えて中分野を内容から判断させる。

各問について次を出す。

| 項目 | 内容 |
|---|---|
| `no` | 問番号 |
| `text` | 問題文（図はテキスト化せず `〔図〕` と記す） |
| `choices` | ア〜エ |
| `answer` | ①の解答キーの値をそのまま入れる（解き直さない） |
| `field` | 中分野コード（`tools/ap_fields.py` の一覧） |
| `explanation` | 正解の根拠＋各誤答が誤りである理由 |
| `figure` | 図の位置 `{page, top, bottom}`（ページ高さに対する割合） |
| `confidence` | `high` / `medium` / `low` |

### ③.5 抽出結果の解答を監査する（③が全部終わってから）

```bash
py -3.12 tools/audit_answers.py
```

**これは必ず実行すること。** ④は正解を解答PDFで上書きするのでバンクの `answer` は常に正しくなるが、
**解説は抽出時点の `answer` を前提に書かれている**。抽出側がずれていると
「正解はア」と表示しながら解説がイを正当化する、という食い違いが残る。この監査はその組合せだけを洗い出す。

実際、2,640問のうち十数件でこのずれが起きた。原因はほぼ「抽出エージェントが解答キーJSONを読み違え、
自分の正しい計算を捨ててキー（と思い込んだ値）に合わせた」というもの。検出されたら
`ap-bank-qc` エージェントに渡し、元画像を見たうえで**解説を正解に沿って書き直させる**。

> **順序に注意**: ③のエージェントが動いている最中に同じ回を `ap-bank-qc` に修正させてはいけない。
> 抽出エージェントが後からファイルを書き直して修正が失われる。
> **③が全部終わってから**監査 → 修正 → ④の順に進めること。

### ④ バンクを組み立てる

```bash
py -3.12 tools/build_bank.py
```

- `work/extracted` に結果がある回だけを対象にする
- **正解は必ず解答 PDF を正典**とし、③の読み取りと食い違ったら報告して解答 PDF を採用する
- **中分野の系統が解答 PDF の大分野（T/M/S）と一致するか照合**する。ここで③の読み取りミスが機械的に検出できる
- `figure` の位置から、余白にスナップして図表を切り出し PNG（data URI）として埋め込む
- 結果は `tools/build_report.md` に出る。`needsReview` が立った問題はアプリ側でも「※要確認」と表示される

生成後はアプリを開き直すだけで新しいデータが自動で取り込まれる（`stamp` が変わると再取り込み）。
**学習履歴は問題データを差し替えても消えない**（問題 ID 別に管理している）。

### ⑤ 総点検する

```bash
py -3.12 tools/validate_bank.py
```

④とは独立の経路で `questions.json` だけを入力に検証し直す（生成側のバグを拾うため）。見ているのは
問番号の連続性・解答PDFとの一致・系統の整合・図表PNGの健全性・`version.json` とのスタンプ一致。

再出題の整合も見る。IPA は同じ問題を別の回で**選択肢の並びを変えて**出すので、正解の記号が違うのは正常。
検査するのは (1) 選択肢の中身まで同じ版で正解が食い違わないか（食い違えばエラー）、
(2) 分野の割当が回をまたいで揃っているか（揃っていなければ警告）。
(2) が出たら `tools/field_exceptions.json` の `field_overrides` に少数派を追記して多数派に揃える。

## 3. 分野の体系

IPA シラバスの大分野・中分野に準拠。`tools/ap_fields.py` と `app/js/fields.js` の
コードを一致させること。

| 系統 | 中分野 |
|---|---|
| テクノロジ系 | T01 基礎理論 / T02 アルゴリズムとプログラミング / T03 コンピュータ構成要素 / T04 システム構成要素 / T05 ソフトウェア / T06 ハードウェア / T07 ヒューマンインタフェース / T08 マルチメディア / T09 データベース / T10 ネットワーク / T11 セキュリティ / T12 システム開発技術 / T13 ソフトウェア開発管理技術 |
| マネジメント系 | M01 プロジェクトマネジメント / M02 サービスマネジメント / M03 システム監査 |
| ストラテジ系 | S01 システム戦略 / S02 システム企画 / S03 経営戦略マネジメント / S04 技術戦略マネジメント / S05 ビジネスインダストリ / S06 企業活動 / S07 法務 |

分野は問題画面・詳細画面から個別に直せる（端末内の上書き設定として保存される）。

## 5. 注意

- IPA の試験問題の著作権は IPA に帰属する。本アプリは**個人の学習用**に手元で変換して使うもので、再配布はしない。
- ③は画像からの読み取りなので、原文と細部が違う可能性がある。`※要確認` が付いた問題と、
  計算問題の数値は `work/pages/` の元画像で確かめられる。
- 端末のストレージを消すと学習履歴も消える。設定画面から定期的に書き出しておくとよい。
